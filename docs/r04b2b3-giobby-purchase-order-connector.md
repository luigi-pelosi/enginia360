A distinct versioned purchase fingerprint covers the verified non-secret administrative binding **plus all sorted non-null `PurchaseOrder:*` mapping fields**. Original configuration can be restored; **historical descriptors containing only the earlier sales fingerprint remain held with no automatic repair/backfill**. No new policy to replace such requests is introduced.

## Wire surface, completion and uncertainty

Only `GET loggeduser`, `POST purchases/orders?simulation=false`, `GET purchases/orders?offset=0&limit=5&freeText=<vendor name>&docStatus=CREATED`, `GET purchases/{id}/orders` are generated. No sales invoice, stock mutation, transformation, cancellation, receipt or delete endpoint.

Outbound: type2/orderType1, `idVendor` string, `idContact: null`, explicit BU/numerator, current UTC epoch-millis string, EUR, stable `E360-PO-{intent UUID without hyphens}` correlation reference, empty payments, exactly one row with explicit material/attribute0/position type, source description, q6 quantity and accepted price, VAT/storage. No `docNumber`, client status, server-idempotency header or invented numeric-contact mapping.

HTTP200/business200/error0 + positive integer `idDocument` is an acknowledgement only. Completion requires detail readback matching ID/type/CREATED, vendor/reference, exactly one row, description, quantity, **exact q6 row price**, material/storage/VAT/position type. Header totals are deliberately not compared at q6: observed provider totals round to two decimals, and no new fiscal/rounding policy is inferred. Numeric contact is server resolved; no independent contact assertion is invented.

Before any external call, the worker commits Uncertain. Thereafter only GET recovery is allowed, including after timeout, 500, malformed response, crash/expired lease or divergent readback. The bounded name+state list is filtered by exact reference/vendor/type/status; duplicate matches, empty and every full five-row page are uncertain, even with one matching reference (duplicates can be outside that page). `totalCount` is not a completeness signal. A unique matching header on a non-full page permits detail verification, never unconditional completion. No empty lookup or arbitrary provider error authorizes another POST. Persisted Completed with missing Inventory outcome finishes recording without a new POST. Pre-flight `NotSent` (missing config/binding/identity) can return to Queued because no business write occurred; a Status refusal never returns an attempted request to Queued.

Separate purchase worker/lease from sales. Lease validation exceeds **three** sequential bounded HTTP calls (identity + list + detail). No transaction is held over HTTP; exact lease timestamp fences saves. Transient ambiguity retries GET with bounded exponential delay, no claim of provider idempotency or exactly-once. Host standard TLS validation, exact allowlist, redirect denial, 65,536-byte body cap and body-read deadline remain mandatory. HTTP loggers are removed; API logs contain technical IDs/status/error codes only.
