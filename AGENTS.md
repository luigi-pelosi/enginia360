# Engineering standards

Read all of PROJECT_CHARTER.md before editing. This repository is Enginia360, not SmartData. Do not modify or depend on SmartData. B01–B14 and C00 are complete. Current post-slice authorization is D74–D75: autonomous bounded development of P00/UI01/R00–R06, as defined in docs/productization-plan.md, for workshop pilot operations with external ERP administration, preserving internal accounting capability. Giobby is the first ERP; SAP custom BTP consultant API is excluded this sprint. D76 confirms configurable unilateral integration direction per customer/domain in company settings (Enginia360 to Giobby or vice versa). Retain a single tenant-wide shared-master authority under D26/D65, separate company extensions/prices/stock. Select the concrete working profile at setup before dependent writes; not a blanket UI/runtime block. No concurrent bidirectional writers or automatic/retroactive authority switching is approved. Owner authorizes delivery through conventional commits, PR, exact-head CI, merge and merged-main CI. P00 is documentation/tests only, with no app changes; UI01 starts only after verified P00 merge. No go-live, real data, purchases or deployment authorized. No new persistent manual environment or public deployment is authorized. Bootstrap, Tailscale 443 → localhost:9119 and 25 retained volumes/backups/configurations remain protected. Independent parallel work is allowed; stop on genuinely missing policy, not routine approval.

- Implement only the authorized behavior, with a failing executable test before production code (RED → GREEN → REFACTOR). Report exact commands and outcomes.
- Use English identifiers, immutable contracts, nullable reference types and warnings as errors. Italian is the initial UI language. No speculative abstractions or domain modules.
- Keep tenant, identity, fiscal and accounting decisions pending human approval. Never add business data, fake demonstrations or authentication without explicit scope.
- Never commit secrets, personal data, generated build files or local configuration. Validate all untrusted input. Correlation tokens are technical identifiers, never authentication or trusted identity.
- Lock dependencies and explicitly pin image versions. Update locks intentionally and run security audits; do not disable audit warnings to force builds through.
- Run API integration tests, UI tests/typecheck/build, Compose health checks and HTTP smoke tests. CI is not verified until executed on the remote platform.
- Containers must run nonroot, read-only, with dropped capabilities, no privilege escalation, bounded resources/logs and no public backend/database ports.
- Document limitations and rollback for every deployment change. Do not claim availability guarantees from a single-host bootstrap. Never create an interface or service solely for hypothetical future requirements.
